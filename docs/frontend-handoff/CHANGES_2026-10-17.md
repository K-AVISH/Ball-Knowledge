## 2. The dashboard shows memes, not names (Ask 2)

This is the owner's standing rule now: **the Live dashboard never names a gesture.**

| Before | Now |
|---|---|
| Right column: Recognition panel (status tag, gesture name in green, hint), Meme result panel (image, name tag, rating tag, title falling back to the gesture name, "not set" lines), Top scores table | One **Meme** panel (`ui.result_card`): the meme in a 4:3 frame, the confidence meter under it, nothing else |
| States shown as headlines with tags | Each state puts a short message in the meme's frame: No trained model, Model cannot be used, Camera off, Waiting for video, Starting, Prediction failed, No hand in view, Unrecognised (amber edge, amber meter), Hold it steady, No gesture |
| Meter only in some states | Meter always present. It shows the score being judged, or `n/a` with an empty bar |
| "Recognised in 5 of 7 frames ... not a calibrated probability" hint | Moved into the meter's tooltip (`title`) |
| "Retrain needed" tag inside the panel | Amber notice at the top of the page (`ui.stale_notice`) |
| "No Ball Knowledge rating or description yet for: First meme, ..." notice | Removed |
| Live statistics tile "Latest gesture: Meme 3" | "Latest meme" with a small picture of the meme |
| Recent detections "Gesture" column with names | "Meme" column with small pictures (`ui.meme_thumb`) |

Kept on purpose:
- A meme still shows only for a steady gesture (4 of the last 7 frames). Uncertain means no meme.
- The owner's own meme title, "Ball Knowledge: ..." rating and description appear under the
  meter **only when set**. None are set today. If the owner wants them never shown, delete the
  `owner` part of `ui._meme_view`.
- Gesture names still appear where something must be fixed ("No meme set" for a gesture,
  the top notice "No usable meme image yet for: ...") and on the collector, performance and
  Memes pages, where the owner needs them to record, judge and edit.
- A gesture with no usable image falls back to its name in the thumbnails, since nothing else
  can identify it.

The Memes page preview (`ui.meme_card(..., preview=True)`) is the same meme frame without the
meter, so it shows what the dashboard will show.

## 3. Refinements (Ask 1)

| Found | Change |
|---|---|
| Camera off: a 152px strip with a small icon; the page jumped about 300px when video started | The camera iframe's placeholder is a 4:3 frame (`_IFRAME_CSS`), the shape the camera is asked for |
| The camera button had Material's raised shadow, a click ripple and a darker hover | Flat: no shadow, no ripple, dark text, hover `#45c983` like the other green buttons |
| Camera denied showed the library's dark red box | Styled like the page's red notices; shown above the frame, not inside it |
| Notices used Streamlit's olive yellow and blue, outside the palette | `st.warning`, `st.error`, `st.success` and the new `ui.notice` share one look: 1px border, faint tint of `--warn`, `--bad` or `--accent`, neutral grey for info, text `--text` |
| Dashboard notices said "Memes page" with no link | `ui.notice` with an in-app link (Streamlit's own notices always open links in a new tab) |
| A wrapped tile label pushed its value 15px below its neighbours | Tiles use CSS subgrid, so values in a row line up |
| Model performance showed the tag "softmax regression gradient descent", against the copy rule | Tag reads "softmax regression" |
| Memes table: twenty plain "Set" / "Not set" words | Tags: Set green, Not set grey, image Missing amber |
| At 390px those tags wrapped into two-line boxes and tables overflowed | Under 480px tables tighten and a tag in a table shows as its coloured word. Every table on Memes and Model performance now fits at 390px |
| Memes preview linked to the Memes page while on it | Says "in the form on this page" where a link would have been |
| Every browser tab was titled "Ball Knowledge Vision AI" | "Live dashboard \| Ball Knowledge Vision AI" and so on, per page |
